# 🎯 팩토리 메소드 vs 추상 팩토리 정리

## 1. 개념 정리

### ✅ 팩토리 메소드 (Factory Method)
- **정의**:  
  객체 생성 로직을 서브클래스(혹은 구체 팩토리)에 위임.  
  즉, **“어떤 객체를 만들지”는 서브클래스가 결정**.  
- **핵심**:  
  - 객체 생성의 **한 지점**을 추상화 (`createProduct()` 같은 메소드).  
  - 단일 제품 계열 안에서 다양한 객체 생성 가능.  
- **예시 (스타크래프트)**:  
  - `Barrack.createUnit("Marine")`  
  - `Starport.createUnit("Wraith")`  
  - 건물마다 자신이 생성할 수 있는 유닛만 관리 → **조건문은 남을 수 있음**.

---

### ✅ 추상 팩토리 (Abstract Factory)
- **정의**:  
  서로 관련 있는 객체들의 **집합(제품군)**을 일관성 있게 생성하는 인터페이스 제공.  
- **핵심**:  
  - 여러 팩토리 메소드들이 모여 **세트(제품군)**를 이룸.  
  - 클라이언트는 구체 클래스 몰라도, 제품군을 통째로 선택 가능.  
- **예시 (AoM / 심즈)**:  
  - `GreekFactory.createInfantry()` → Hoplite  
  - `GreekFactory.createTemple()` → GreekTemple  
  - `EgyptianFactory.createInfantry()` → Spearman  
  - `EgyptianFactory.createTemple()` → EgyptianTemple  
  - 가구 세트 (ModernFactory → 모던 의자/테이블/침대).

---

## 2. 차이점

| 구분 | 팩토리 메소드 | 추상 팩토리 |
|------|---------------|-------------|
| **초점** | 객체 생성의 한 지점을 추상화 | 객체군(제품군) 전체를 추상화 |
| **범위** | 단일 계열 안에서 "무엇을 만들까?" | 여러 계열(세트)에서 "일관성 있게 만들까?" |
| **구조** | 추상 Creator + 팩토리 메소드 1개 | 여러 팩토리 메소드가 묶인 추상 팩토리 |
| **게임 예시** | 스타크래프트 (건물 → 유닛 하나씩) | AoM/심즈 (문명/스타일 세트 전체) |

---

## 3. 관계

- **팩토리 메소드**는 **하나의 객체 생성 메소드 추상화**에 초점.  
- **추상 팩토리**는 **여러 팩토리 메소드**가 모여 **제품군**을 일관성 있게 생성하는 것에 초점.  
- 따라서:  
  - 추상 팩토리 내부 **구현 방식**으로 팩토리 메소드가 자주 사용됨.  
  - 하지만, 팩토리 메소드를 쓴다고 해서 자동으로 추상 팩토리 패턴이 되는 것은 아님.  
  - 쉽게 말해: **추상 팩토리 = 팩토리 메소드들의 집합 + 제품군 일관성 유지**.

---

## 4. 요약 예시

- **스타크래프트 (Factory Method)**  
  - 건물마다 유닛 생성 책임만 있으면 충분 → 단일 객체 생성 추상화.  

- **AoM (Abstract Factory)**  
  - “그리스 문명”을 고르면 → 그리스 스타일 유닛, 건물, 신 능력이 일관되게 제공.  

- **심즈 (Abstract Factory)**  
  - “모던 가구 세트”를 고르면 → 모던 의자/테이블/침대가 세트로 생성.  

---

👉 결론:  
- **Factory Method** = “객체 하나 생성 책임 위임”  
- **Abstract Factory** = “관련 객체군(세트) 일관성 있게 생성”  
- **관계** = 추상 팩토리 내부에서 팩토리 메소드가 구현되는 경우 많음.
